# RQ01 e RQ04 — idade do repositório e tempo desde a última atualização

## 1. Hipóteses informais (escritas antes de olhar os dados coletados)

**RQ01 — Sistemas populares são maduros/antigos?**
Hipótese: sim. Repositórios com muitas estrelas tendem a acumular popularidade ao
longo do tempo (efeito de rede: mais estrelas atraem mais visibilidade, que atrai
mais estrelas), então espero que a maioria dos repositórios no top de estrelas
tenha vários anos de existência, com poucos casos recentes (menos de 1-2 anos)
que teriam ganhado popularidade de forma muito rápida/viral.

**RQ04 — Sistemas populares são atualizados com frequência?**
Hipótese: sim, para a maioria. Um repositório com muita visibilidade tende a
receber mais contribuições e atenção de manutenção, então espero que a maior
parte tenha `pushedAt` recente (dias/semanas). Porém espero também um grupo
menor de repositórios "populares porém estagnados" — ex.: listas `awesome-*` ou
material educacional que não precisa de atualização constante — com tempo desde
o último push bem maior (meses/anos).

## 2. Extração e cálculo

Spec usada: [`specs/github-rq1-rq4-v1.yaml`](../specs/github-rq1-rq4-v1.yaml).
Ela busca `createdAt`, `pushedAt`, `nameWithOwner` e `url` de uma amostra de 10
repositórios (ordenados por estrelas), suficiente para a validação manual desta
Issue antes de integrar ao script único do grupo.

O cálculo é feito em [`src/index.ts`](../src/index.ts), na função
`flattenRepositories`, usando a data/hora em que o script é executado
(`dataColeta`) como referência — exportada também como coluna `data_coleta` no
CSV, para que os números sejam reproduzíveis:

- **RQ01 — `idade_anos`**: `(dataColeta - createdAt) / 365.25 dias`, arredondado
  para 2 casas decimais.
- **RQ04 — `dias_desde_ultima_atualizacao`**: `(dataColeta - pushedAt)` em dias
  corridos, arredondado para o inteiro mais próximo.

Para rodar:

```bash
npm run dev -- ./specs/github-rq1-rq4-v1.yaml
```

O CSV é salvo em `data/github-rq1-rq4-v1_<timestamp>.csv`.

## 4. Registro de discrepâncias

- `openclaw/openclaw`: `pushedAt` coletado (`2026-08-12T18:44:41Z`) ficou
  desatualizado em relação ao valor atual da API (`2026-08-12T19:57:33Z`) —
  causa: o repositório recebeu um novo push entre o momento da coleta e o
  momento da validação. Não é um bug de extração; `pushedAt` reflete o estado
  no instante da coleta (`data_coleta`), por isso a métrica é sempre relativa
  a essa data, como documentado na Seção 2. `createdAt` (fixo) bateu
  normalmente.
- Nenhuma outra discrepância encontrada nos 10 repositórios verificados.
