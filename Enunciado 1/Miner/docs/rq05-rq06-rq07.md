# RQ05, RQ06 e RQ07 — Linguagens, Razão de Issues e Cruzamento por Linguagem

## 1. Hipóteses informais (escritas antes de olhar os dados coletados)

**RQ05 — Sistemas populares são escritos nas linguagens mais populares?**
Hipótese: Sim. Baseando-se no **GitHub Octoverse** (nossa fonte de referência definida), linguagens como JavaScript, Python e TypeScript dominam o ecossistema atual. A expectativa é que repositórios com a maior quantidade de estrelas acompanhem essa tendência, pois grandes comunidades impulsionam o engajamento (stars) e fomentam projetos nessas tecnologias.

**RQ06 — Repositórios populares têm uma alta razão de issues fechadas?**
Hipótese: Sim. A expectativa é que projetos com muitas estrelas possuam equipes e comunidades ativas o suficiente para triagem e resolução contínua de issues. Espera-se uma mediana de razão (issues fechadas / total de issues) superior a 0,7 (70%), indicando que a maioria dos problemas reportados acaba sendo resolvida.

**RQ07 — Há relação entre a linguagem de programação e a razão de issues fechadas?**
Hipótese: Sim. Espera-se que repositórios construídos com as linguagens mais populares (como JavaScript, TypeScript e Python) possuam uma maior taxa de resolução de issues (razão de issues fechadas vs. total de issues). Isso se justificaria pelo tamanho das comunidades ativas, quantidade de contribuidores open-source engajados e pela maturidade do ecossistema de ferramentas de automação (CI/CD) para essas linguagens, que aceleram a triagem e fechamento de problemas.

## 2. Extração e cálculo

Spec usada: [`specs/github-search-v1.yaml`](../specs/github-search-v1.yaml).
Ela busca `primaryLanguage`, `closedIssues: issues(states: CLOSED)` e `totalIssues: issues`.

O cálculo é feito em [`src/index.ts`](../src/index.ts), na função `flattenRepositories`:

- **RQ05 — `linguagem`**: Extraída diretamente do nó `primaryLanguage.name`. Em caso de repositório sem linguagem definida, será salvo como `'N/A'`. A popularidade será cruzada na fase de análise de dados com o relatório do **GitHub Octoverse**.
- **RQ06 — `closed_issues` e `total_issues`**: Extraídos dos nós `closedIssues: issues(states: CLOSED).totalCount` e `totalIssues: issues.totalCount`. O percentual de issues fechadas é representado pela coluna `ratio_closed_issues` (ver RQ07 abaixo).
- **RQ07 — `ratio_closed_issues`**: Calculado através da razão `closed_issues / total_issues`. Se o repositório não tiver issues (`total_issues == 0`), a razão atribuída será `0` para evitar divisões por zero. Este campo serve tanto para a análise geral da RQ06 quanto para o cruzamento por linguagem da RQ07.

Para rodar a coleta completa:

```bash
npm run dev -- ./specs/github-search-v1.yaml
```

O CSV é salvo em `data/github-search-v1_<timestamp>.csv`.
